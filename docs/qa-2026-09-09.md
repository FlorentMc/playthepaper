## Open findings

### 1. High: the web app cannot reopen offline

Reproduction: open the release build online, open Tangram, place a piece, disable the network, then reload the page. Chrome displays `ERR_INTERNET_DISCONNECTED`. Moving a piece in an already-open game still works offline, and the move survives reconnecting.

The generated `build/web/flutter_service_worker.js` only unregisters itself. Chrome reports no active service-worker registration or Cache Storage entries. The app has no replacement mechanism to cache and serve its shell offline. The production configuration also requires app files to revalidate with the server (`infra/nginx/playthepaper.conf:28`, `:43`). Caching puzzle JSON alone does not make the app reopen offline.

Suggested correction: provide a versioned cache for the app shell and its required assets, with an offline navigation fallback and an update strategy. Test a previously visited puzzle and the home page after closing/reopening the installed web app without a connection.

### 2. High: the crossword board overlaps the keyboard and hides its clues on small phones

Reproduction: at 320×568, open `crossword-2026-09-09-en-v1` and dismiss help. The lower board and current-clue bar extend into the keyboard. The clue list has no usable height. Chrome and the font-loaded widget test both report a 64-pixel bottom overflow.

Source: `lib/features/games/crossword/crossword_screen.dart:301`, especially the fixed board above `Expanded(child: clues)` at `:324`.

[Browser screenshot](../build/qa/crossword-small-phone.png)

The crossword also overflows in landscape. Daily Word has a separate 39-pixel vertical overflow at 844×390. These layouts need to account for available height, keyboard height, and story text, with scrolling or an alternate arrangement where necessary.

### 3. Medium: opening a game does not update the browser URL

Reproduction: open the home page, select Nonogram, fill a cell, and inspect the address bar. It remains `/`. Refresh returns to the home page. The tile correctly says "In progress", and the saved cell remains when the game is reopened, so this is a navigation failure rather than lost progress. Copying the browser address also copies the home-page address instead of the puzzle address. Opening a permanent `/p/<id>` link directly works.

Source: `lib/features/home/edition_view.dart:147` uses `context.push`, while `lib/app.dart:81` leaves go_router's imperative-URL option at its default. The installed go_router 17.5.0 declares `optionURLReflectsImperativeAPIs = false` in `lib/src/router.dart:340`.

Suggested correction: make browser addresses reflect the displayed route while preserving the expected back stack. Verify refresh, browser Back/Forward, and copying the address for current and archived games.

### 4. Medium: export/import loses the unlimited 2048 board and best score

Reproduction: play an unlimited game, export progress, and import it into empty local storage. `MergeExtras.load(store).unlimitedState()` returns null. The free-play board and best score are missing from the export, as are stored finished daily boards.

Source: `lib/storage/local_store.dart:197` exports progress/results/settings/favourites but omits `extra:*` entries. 2048 stores these values through `lib/features/games/merge/merge_extras.dart`.

Suggested correction: include validated, namespaced game extras in the portable export format and define sensible merge rules for best scores, active games, and finished boards.

### 5. Medium: import ignores the settings included in its own export

Reproduction: export with Dark appearance, Reduce motion, and Show timers enabled. Change those settings to Light/off/off, then import the export. All three remain unchanged, although the export contains their original values.

Source: `lib/storage/local_store.dart:203` exports settings; `importJson` at `:209` never reads that field.

Suggested correction: restore valid exported settings according to a documented import policy and notify settings listeners.

### 6. Medium: Tangram can drag a piece underneath the selected piece

Reproduction: overlap the large triangle and square, then select the triangle so it is drawn on top. Start a drag in the overlap. The square is selected for dragging instead.

Source: `lib/features/games/tangram/tangram_board.dart:130` hit-tests in map insertion order. Painting at `:173` uses piece order and then draws the selected piece last. The hit-test order therefore differs from what the player sees. This was reproduced through a widget pointer gesture, not only by calling the hit-test function directly.

Suggested correction: share one stacking order between painting and hit testing, and hit-test from the topmost visible piece downwards. Cover selection changes and pieces placed in different orders.

### 7. Medium: enlarged text clips essential Sudoku controls and Nonogram clues

At 390×844 and 200% text scaling with the actual fonts:

| Game | Reproduced error |
| --- | --- |
| Sudoku | Each digit key's number/count column overflows vertically by 41 pixels |
| Nonogram 5×5 | Column clues overflow vertically by 9.3 pixels |
| Nonogram 10×10 | Column clues overflow vertically by 22 pixels |

Sources: `lib/features/games/sudoku/sudoku_controls.dart:165` fixes the digit-key height at 52; `lib/features/games/nonogram/nonogram_board.dart:132` calculates clue space without the text scale, while clue text itself scales.

Suggested correction: allocate space using actual scaled text dimensions and reflow controls where needed. Preserve enlarged text instead of suppressing the user's accessibility setting.

### 8. Low: Tangram's shared result reveals the figure name

`TangramScreen` puts the silhouette name in `GameResult.note` (`lib/features/games/tangram/tangram_screen.dart:146`). `ShareService.resultText` includes `result.summary()`, which returns that note. The shared text therefore contains the figure's name even though the game treats it as a completion reveal and promises spoiler-free sharing.

The regression case emits `Cat in 0:58`; the actual 9 September completion produced the note `Rocket in 1:30`. Checking only `shareLines`, as the existing test does, misses the leak.

Suggested correction: keep the figure name in the on-device reveal and use time/hints in the portable score summary. Test the complete share text.

## Resolution (same day, commit after `cc64f17`)

| # | Finding | Fix | Regression test |
|---|---|---|---|
| 1 | Web app cannot reopen offline | `web/sw.js`: shell precached on install, every same-origin GET cached network-first, navigation falls back to the cached shell; registered from `index.html`; builds use `--pwa-strategy none` so Flutter's self-unregistering worker never replaces it (workflow, README, nginx notes updated) | Verified with Playwright: after one online visit, the `/p/<id>` deep link and the home page both reopen with the context offline |
| 2 | Crossword overlaps the keyboard on small phones; crossword and Daily Word overflow in landscape | Narrow crossword layout budgets the height (keyboard, clue bar, teaser, info) and sizes the board from what is left, dropping the clue list when fewer than 96 px would remain; wide layout's clue columns scroll; Daily Word tiles shrink to the height available with a smaller gap | `test/features/layout/layout_audit_test.dart` with the shipped fonts at 390×844, 320×568, 844×390 and 200 % text |
| 3 | Browser address does not follow a pushed game | `GoRouter.optionURLReflectsImperativeAPIs = true` in `buildRouter` | Manual (URL bar); the flag is set where the router is built |
| 4 | Export/import loses 2048 extras | `exportJson` carries every `extra:*` entry; `importJson` adds missing keys and merges JSON objects field by field (local wins, `best…` numbers take the maximum, maps unite) | `test/content/local_store_test.dart` |
| 5 | Import ignores exported settings | `importJson` applies the exported settings and notifies listeners | same file |
| 6 | Tangram drags the piece underneath | One `stackingOrder` shared by the painter and `pieceAt`, which now hit-tests from the top | `test/features/tangram/tangram_hit_test.dart` |
| 7 | Enlarged text clips Sudoku keys and Nonogram clues | Digit-key height and clue space scale with `MediaQuery.textScaler` | layout audit at 200 % text |
| 8 | Tangram share reveals the figure name | The figure name stays in the on-device reveal; the result note is no longer set, so the summary and share text carry only time and hints | `tangram_screen_test.dart` checks the full share and challenge text |
